# 234

Quadratic, cubic, and quartic equation solver.

**Converted from:** `234.C` (M. W. Klotz, 2/01), `MWKC/Math/234.zip`
**Go source:** `MWKGo/234/234.go`

## Purpose

Solves polynomial equations of order 2, 3, or 4 with real
coefficients, returning every root (real or complex).

## Inputs

| Prompt | Default |
|---|---|
| Order of equation to solve (2,3,4) | 2 |
| Coefficient for each term, order down to 0 | 0 |

## Output

The equation as entered, and each root's real and imaginary parts.

## Method

- **Quadratic**: the standard quadratic formula.
- **Cubic**: Cardano's method — the trigonometric form (three real
  roots) when the discriminant is negative, the algebraic form (one
  real root plus a conjugate pair) otherwise.
- **Quartic**: Ferrari's method — a resultant cubic is solved first
  (via the same cubic solver), and one of its three roots, whichever
  yields a non-negative value for `R^2`, is used to factor the
  quartic into two quadratics. The original program's own comment
  notes it hasn't explored the case where `R` might need to be
  imaginary; this conversion preserves that same limitation, reported
  as an explicit error when no resultant-cubic root gives a workable
  `R^2 >= 0` (a genuine floating-point knife-edge exists here: see
  Worked Example, below).

## Worked Example

No worked numeric example was included with the original program. As
independently verifiable checks, several polynomials with
known roots were used: for a solver of this kind, the strongest test
is the polynomial's own defining property, so each returned root was
substituted back into the original polynomial and confirmed to
evaluate to (approximately) zero, for:

- `x^2 - 5x + 6 = 0` (roots 2, 3) and `x^2 + 1 = 0` (roots `i`, `-i`)
- `(x-1)(x-2)(x-3)` (three real roots) and `(x-1)(x^2+1)` (one real,
  two complex)
- `(x-1)(x-2)(x-3)(x-4)` (four real roots) and `(x-1)(x-2)(x^2+1)`
  (two real, two complex)

A further check, `(x^2+1)(x^2+4) = 0` (roots `i, -i, 2i, -2i`),
exposed a genuine floating-point fragility inherited from the
original algorithm: its resultant cubic's only usable root lands
exactly on Ferrari's method's `R^2 >= 0` boundary, where ordinary
floating-point rounding can tip the computed value to a
vanishingly small negative number and cause the whole solve to be
rejected as having "no usable real solution to resultant cubic",
even though a solution exists. This isn't unique to the Go port —
the original C algorithm has the identical arithmetic at the identical
boundary — so it's preserved rather than patched with an
epsilon tolerance the original never had. This conversion's test
suite checks for the error only informationally (it doesn't require
either outcome), since whether it reproduces depends on
platform-specific floating-point rounding, not on program logic.
